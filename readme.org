#+TITLE: dc Calculator — User Manual
#+DATE: 2026-11-04

* 1. Overview

This calculator is a Reverse Polish Notation (RPN) desk calculator built on top of an embedded implementation of the Unix ~dc~ language — the same stack-based postfix language Unix systems have shipped since the 1970s. Every button you press ultimately becomes a short ~dc~ command string that runs through that engine.

*The stack.* Instead of typing ~3 + 4 =~, you enter numbers onto a stack and then press an operator, which pops the values it needs and pushes the result. The display shows four stack levels at once, HP-style:

| Row | Meaning                                                                 |
|-----+-------------------------------------------------------------------------|
| T   | Third-from-top of stack                                                 |
| Z   | Second-from-top                                                         |
| Y   | Second number down                                                      |
| X   | Top of stack — the "active" register, editable, where typed digits land |

Typing ~2~, pressing *enter*, typing ~3~, then pressing *+* computes ~2 + 3~: ~2~ sits in X, enter pushes it up and clears X for new input (this is called /stack lift/), ~3~ is typed into the now-empty X, and ~+~ pops X and Y, adds them, and pushes ~5~ back into X.

*Theme.* The sun/moon button in the toolbar toggles dark and light mode; the choice is remembered between sessions.

*Two independent calculators in one app.* The button keypad described in this manual and the *Direct Console* (Section 4) are two separate ~dc~ engines with separate stacks and separate saved state — using one does not affect the other. The keypad is for everyday arithmetic; the Direct Console is for typing raw ~dc~ programs directly.

* 2. Keypad Reference

*Digits and entry.* The number grid (0–9, ~.~, sign-change) types into X. Press *enter* to push the value and start a fresh number (this is the "lift" described in Section 1). If you press an operator without pressing enter first, the calculator uses whatever is already in X and Y — you don't have to press enter before every operator, only when you want to duplicate or separate values on the stack.

*SHIFT layers.* Each key can do up to three things:

| Layer        | How                                      | Example                     |
|--------------+------------------------------------------+-----------------------------|
| Main         | Press the key                            | ~÷~ divides                 |
| Orange SHIFT | Press the orange SHIFT key, then the key | ~÷~ key becomes ~x̄~ (mean) |
| Blue SHIFT   | Press the blue SHIFT key, then the key   | ~÷~ key becomes ~ȳ~         |

The small label above/below each key shows what its shifted functions are. SHIFT stays "on" only for the next keypress, then releases automatically.

*Popup menus.* Keys with a small indicator (const, stats, conv, more, clear) open a popup of related functions when SHIFTed. Tap outside the popup to close it without choosing anything. These group functions that would otherwise need a key of their own:

| Popup | Holds                                                                                                                               |
|-------+-------------------------------------------------------------------------------------------------------------------------------------|
| const | Physical/math constants                                                                                                             |
| stats | Read-only peek at the Σ-statistics accumulator registers (the key itself runs n-th root — nCr/nPr live elsewhere, see the Appendix) |
| conv  | Swap X/Y, unit-style conversions                                                                                                    |
| more  | Drop top of stack, GCD, LCM, prime factorization                                                                                    |
| clear | Clear all (CLALL), clear statistics registers (CLΣ), clear stack (CLSTK)                                                            |

*LASTX.* Every operation that consumes X saves the previous value of X into a hidden LASTX register, recalled with the *lastx* key — useful for "oops, I meant to keep that" or for repeating a calculation with a factor.

*Registers / detail view.* The *▼* button opens an overlay showing LASTX and the contents of any named registers currently in use — handy when running your own keystroke programs (Section 3) that store intermediate values.

*Backspace / dow.* The ⌫ key backspaces while you're typing a number; SHIFTed, it reads whatever is in X as an 8-digit ~YYYYMMDD~ date and replaces it with the day-of-week name.

*Mobile note:* the X-register field is read-only until you tap it (this stops the on-screen keyboard popping up every time you tap a calculator button); tap it to edit or copy a value by hand.

* 3. Keystroke Programming

Most keys run a single operation, but several run multi-step ~dc~ macros behind the scenes — and a few workflows need more than one keystroke in a deliberate order. This section walks through the ones worth knowing.

** Combinations and permutations

"5 choose 2" (nCr):

1. Type *5*, press *enter*
2. Type *2*
3. SHIFT-blue → *nCr* (on the ~√x~ key)

Result: ~10~. *nCr* counts the /unordered/ ways to choose r items from n: choosing 2 of 5 gives 10 groups, and picking A-then-B counts the same as B-then-A.

*nPr* counts the /ordered/ ways (permutations): how many ways can 5 people fill 2 distinct jobs (say president and treasurer)? SHIFT-blue on the ~x²~ key:

1. Type *5*, press *enter*
2. Type *2*
3. SHIFT-blue → *nPr* (on the ~x²~ key)

Result: ~20~ (5 × 4). In both cases Y is the pool size n and X is the number chosen r. Note nPr = nCr × r!, so 20 = 10 × 2.

** GCD, LCM, prime factorization

Greatest common divisor of 48 and 18:

1. Type *48*, press *enter*
2. Type *18*
3. SHIFT → *more* popup → *GCD*

Result: ~6~, the largest number that divides both 48 and 18 evenly.

*LCM* — the least common multiple — is the smallest number that both inputs divide into evenly. It is what you need to put fractions over a common denominator. Least common multiple of 4 and 6:

1. Type *4*, press *enter*
2. Type *6*
3. SHIFT → *more* popup → *LCM*

Result: ~12~ (12 is the first number in both the 4s and the 6s: 4, 8, *12* and 6, *12*). Another: 12 and 18 gives ~36~.

*PF* — prime factorization — breaks one number into the primes that multiply to it. It takes a single value in X. Factor 60:

1. Type *60*
2. SHIFT → *more* popup → *PF*

Result: the factors ~2 2 3 5~ (shown as ~n = 2 2 3 5~), because 2 × 2 × 3 × 5 = 60. A prime comes back as itself (97 gives ~n = 97~), and 84 gives ~2 2 3 7~.

** Statistics, all together

All of the statistics keys share one pool of hidden state, built up with *Σ+* one data point at a time. It's worth understanding as one workflow rather than as separate buttons, because several of them depend on exactly what Σ+ stores.

*What Σ+ actually does.* Press /Σ+/ (SHIFT on *+*) with a value in X (one-variable stats) or with X and Y both loaded (two-variable stats, e.g. X=x, Y=y for a regression point). It does two things at once:

1. Updates six running-sum registers: n (count), Σx, Σy, Σx², Σy², Σxy.
2. Appends the raw x and y values to two internal arrays, so later lookups that /can't/ be computed from sums alone (median, mode) still have the actual data to work with.

/Σ−/ (SHIFT-blue on *+* — the same key as Σ+, one layer deeper) reverses the most recently accumulated point — it un-sums it from the six registers and drops it from the arrays. There's no "undo history" beyond the single most recent entry, so if you need to remove an older point, clear and re-enter (SHIFT → *clear* popup → *CLΣ*).

*Reading the raw accumulators.* The *stats* popup (SHIFT or SHIFT-blue on the ~ˣ√y~ key) doesn't run a function — it's a read-only peek at the six registers themselves (nΣ, Σx, Σx², Σxy, Σy, Σy²), handy for checking your data is accumulating the way you expect before trusting a derived result.

*One-variable statistics* (you only ever loaded X before each Σ+):

| Key                        | Formula                         | Notes                                                                                                                                                   |
|----------------------------+---------------------------------+---------------------------------------------------------------------------------------------------------------------------------------------------------|
| *x̄* (SHIFT on ÷)          | Σx / n                          | Mean                                                                                                                                                    |
| *σ* (SHIFT-blue on ±)      | √[(Σx² − (Σx)²/n) / n]          | /Population/ standard deviation — divides by n                                                                                                          |
| *s* (SHIFT on ±)           | √[(Σx² − (Σx)²/n) / (n−1)]      | /Sample/ standard deviation — divides by n−1 (Bessel's correction); use this one unless you specifically have the entire population, not a sample of it |
| *median* (SHIFT-blue on ×) | middle value of the sorted data | Reads the raw array, not the sums — needs at least one Σ+'d point                                                                                       |
| *mode* (SHIFT-blue on –)   | most frequent value             | Also reads the raw array; ties resolve to whichever value the macro encounters first                                                                    |

*Two-variable statistics* (you loaded both X and Y before each Σ+ — e.g. Y=independent variable, X=dependent, or whatever pairing your data represents):

| Key              | Formula                         | Notes                                                                                                                                    |
|------------------+---------------------------------+------------------------------------------------------------------------------------------------------------------------------------------|
| *ȳ* (SHIFT on ÷) | Σy / n                          | Mean of y                                                                                                                                |
| *ŷ* (SHIFT on ×) | m·x + b (least-squares fit)     | Predicted y for an x you put in X /before/ pressing this — it doesn't reuse the x's you already accumulated, only the one currently in X |
| *r* (SHIFT on –) | Pearson correlation coefficient | Ranges −1 to 1; closer to ±1 means a stronger linear relationship                                                                        |

*A full worked example.* Mean and sample standard deviation of {2, 4, 4, 4, 5, 5, 7, 9}:

1. SHIFT → *clear* popup → *CLΣ* (start clean)
2. For each of the 8 values: type the number, press /Σ+/
3. *x̄* (SHIFT on ÷) → ~5~ (the mean)
4. *s* (SHIFT on ±) → ~2.138...~ (sample standard deviation); *σ* (SHIFT-blue on ±) instead → ~2~ (population standard deviation — smaller, because it doesn't correct for sampling from a larger population)

A regression example — fit a line to (1,2), (2,4), (3,5), predict y at x=4:

1. SHIFT → *clear* popup → *CLΣ*
2. Type ~1~, enter, ~2~, /Σ+/ (this is the point (x=1, y=2)); repeat for (2,4) and (3,5)
3. Type ~4~ into X (the x-value you want a prediction for)
4. *ŷ* (SHIFT on ×) → the predicted y at x=4
5. *r* (SHIFT on –) → the correlation coefficient for the three points you entered

The answers (set precision to at least 4 first — type ~4~ and press the *k* key — because at the default of 0 decimals the results are truncated):

| Key               | Result   | Meaning                                                             |
|-------------------+----------+---------------------------------------------------------------------|
| *ŷ* with 4 in X   | ~6.6666~ | Predicted y at x = 4 (the line is y = 1.5x + 0.6667; exactly 6 2/3) |
| *r*               | ~.9819~  | Correlation (exactly 0.98198...); close to 1, a strong linear fit   |
| *x̄*              | ~2~      | Mean of the x values                                                |
| *ȳ*               | ~3.6666~ | Mean of the y values (exactly 3 2/3)                                |
| *s* (for the x's) | ~1~      | Sample standard deviation of the x values                           |
| *σ* (for the x's) | ~.8164~  | Population standard deviation of the x values                       |

Values are truncated, not rounded, at the working precision, so 3 2/3 shows as ~3.6666~ rather than ~3.6667~; raise precision for more digits.

** Date arithmetic

Dates are entered as eight digits, ~YYYYMMDD~. All three date keys take the earlier date in Y and the later date (or the day-count) in X.

*Days between two dates (Δdays).* How many days from January 1 to November 4, 2026?

1. Type *20260101*, press *enter*
2. Type *20261104*
3. Press *Δdays*

Result: ~307~. Entering the dates in the opposite order gives ~-307~.

*Add days to a date (date+).* What date is 90 days after November 4, 2026?

1. Type *20261104*, press *enter*
2. Type *90* (a negative count goes backward)
3. SHIFT → *date+* (the orange function on the *Δdays* key)

Result: ~20270202~ (February 2, 2027).

*Years, months, and days between dates (Δymd).* From March 15 to November 4, 2026:

1. Type *20260315*, press *enter*
2. Type *20261104*
3. SHIFT-blue → *Δymd* (on the *Δdays* key)

Result: ~0y 7m 20d~. And 20240229 to 20261104 gives ~2y 8m 6d~.

*Day of the week (dow).* Type *20261104* and press SHIFT → ⌫ to replace it with ~Wednesday~.

** Rectangular ↔ polar conversion

Both conversions are on the SHIFT layer: *→pol* is on the ~√x~ key and *→rec* is on the ~x²~ key. Angles are in radians.

*Rectangular to polar (→pol).* Put the point's vertical (imaginary) part in Y and its horizontal (real) part in X, so the point (x, y) is entered y first, x last. The result replaces both: *Y gets the angle θ and X gets the magnitude r.*

Worked example — the point x = 4, y = 3 (that is, 4 + 3i), with precision set to 4:

1. Type *3*, press *enter* (Y = 3, the vertical part)
2. Type *4* (X = 4, the horizontal part)
3. SHIFT → *→pol*

Result: Y = ~.6435~ (the angle, in radians, about 36.87°) and X = ~5.0000~ (the magnitude, √(4² + 3²)).

*Polar to rectangular (→rec).* The layout is the same as the →pol result: *Y = angle θ, X = magnitude r.* The result is Y = the vertical part, X = the horizontal part. Starting from the result above, just press SHIFT → *→rec* and you get back Y = ~3~ and X = ~4~ (to within the working precision: at precision 4 you see ~2.9999~ and ~4.0000~, and at precision 8 you see ~2.99999996~ and ~4.00000002~).

To convert degrees to radians first, multiply by π/180.

** Registers: store, recall, and LASTX

The keypad doesn't expose raw ~s~/~l~ register commands directly (that's what the Direct Console is for — Section 4), but LASTX gives you a one-deep "scratch register" for free: after any operation, the value that got replaced is one *lastx* press away, so sequences like "multiply by 3, then also divide the original by 2" become: type the number, enter, ~3~, ~×~, *lastx*, ~2~, ~÷~.

** Factorial

The ~n!~ key (SHIFT-blue on *lastx*) computes the exact factorial of a non-negative integer: type the number and press it; no enter needed first if X already holds the number. For example, ~5~ then *n!* gives ~120~, and ~0~ or ~1~ gives ~1~. The program behind it is written out in Section 6 as a worked example of ~dc~ programming; the key itself is a plain function key like any other.

* 4. The Direct Console

Below the keypad is an expandable text panel — the *Direct Console*. This gives you raw, unwrapped access to the underlying ~dc~ interpreter: whatever you type is run exactly as written, with no button-macro wrapping around it.

*Using it.* Type a line of ~dc~ commands and press *Enter* (on mobile, the Return key on your on-screen keyboard). The line runs immediately and its result is printed on the next line, after which you can keep typing. The panel scrolls and remembers its contents between sessions.

*Why it's separate.* The Direct Console runs its own ~dc~ engine with its own stack, its own registers, and its own saved state — completely independent of the keypad calculator above it. This matters in two ways:

- Anything you ~s~tore in a register here is invisible to the keypad calculator, and vice versa.
- You can experiment freely with stack-clearing commands, base changes (~i~/~o~), or a program that misbehaves without it affecting your everyday keypad calculations.

*Header controls.* The small bar above the text box shows:

- The active app version and the current input/output/scale settings (~i~, ~o~, ~k~) for the Direct Console's own engine — these are independent of whatever base/precision the keypad calculator is using.
- *Copy Text* — copies the whole console transcript to your clipboard.
- *Clear* — wipes the console's text and resets its input (it does not reset registers or the stack — use ~0k~ or re-run your init commands for that, or see the full ~dc~ command list in Section 5 for ways to reset state explicitly).

*Update notice.* The header also quietly checks whether a newer version of the app has been deployed; if so, it offers to reload and update after you confirm — your Direct Console session state is preserved across that reload.

* 5. dc — The Unix Desk Calculator Language

~dc~ ("desk calculator") is one of the oldest programs in Unix history — it predates ~awk~, predates C's standardization, and is still shipped on nearly every Unix-like system today. It is a *stack-based, postfix (RPN)* language: there is no operator precedence to worry about and no parentheses, because the order you write things in /is/ the order they execute in. This app's engine implements the same core language (with arbitrary-precision decimal arithmetic rather than fixed-width numbers).

** Core idea

A ~dc~ program is a string of commands separated by whitespace (whitespace is usually optional between symbols, required between adjacent numbers). Numbers push themselves onto the stack; everything else is a command that pops what it needs and pushes a result. ~3 4 +~ means: push 3, push 4, pop two and push their sum → leaves ~7~ on the stack.

** Stack commands

| Command | Effect                                           |
|---------+--------------------------------------------------|
| ~p~     | Print the top of the stack (without removing it) |
| ~n~     | Pop and print, with no trailing newline          |
| ~f~     | Print the entire stack, top to bottom            |
| ~c~     | Clear the entire stack                           |
| ~d~     | Duplicate the top of the stack                   |
| ~r~     | Swap the top two stack values                    |
| ~R~     | Pop and discard the top of the stack             |

** Arithmetic

| Command   | Effect                                                   |
|-----------+----------------------------------------------------------|
| ~+ - * /~ | Add, subtract, multiply, divide (pop 2, push 1)          |
| ~%~       | Modulo                                                   |
| ~ (tilde) | Division with remainder (pushes quotient then remainder) |
| ~^~       | Exponentiation                                           |
| ~v~       | Square root                                              |

** Registers

~dc~ gives you 256 single-character named storage slots, each of which is itself a tiny stack:

| Command | Effect                                                                           |
|---------+----------------------------------------------------------------------------------|
| ~sX~    | Pop the top of the stack, store it in register ~X~                               |
| ~lX~    | Push a copy of register ~X~'s value onto the stack (does not clear the register) |
| ~SX~    | Pop the top of the stack and push it onto register ~X~'s own internal stack      |
| ~LX~    | Pop register ~X~'s internal stack and push that value onto the main stack        |

~X~ is any single character — by convention letters, but any printable character works as a register name.

** Arrays

Each register can also hold an /array/ — addressable by an index popped off the stack:

| Command | Effect                                                                 |
|---------+------------------------------------------------------------------------|
| ~:X~    | Pop an index, then a value; store the value at that index in array ~X~ |
| ~;X~    | Pop an index; push the value at that index in array ~X~                |

** Macros (bracketed strings)

Text inside square brackets ~[ ... ]~ is not executed — it's pushed onto the stack as a string value (a "macro"). It only runs when explicitly executed with ~x~:

#+begin_example
[1 2 +] x
#+end_example

pushes the string ~1 2 +~, then ~x~ executes it, leaving ~3~ on the stack. This is how ~dc~ does everything a modern language would use functions, loops, and conditionals for — a macro is usually stored in a register (~s~) so it can be invoked (~l~ ... ~x~) or referenced in a conditional, repeatedly.

** Conditionals and branching

~dc~ has no ~if~/~while~ keywords. Instead, a comparison pops two values, and if the comparison holds, it executes whatever macro is stored in a named register:

| Command                         | Effect                                                                |
|---------------------------------+-----------------------------------------------------------------------|
| ~a b >X~                        | Execute the macro in register ~X~ if b > a                            |
| ~a b <X~                        | Execute the macro in register ~X~ if b < a                            |
| ~a b =X~                        | Execute the macro in register ~X~ if b = a                            |
| ~a b !<X~, ~a b !>X~, ~a b !=X~ | Negated forms of the three above (fire when the plain form would not) |

The easy way to read these: the value pushed last (b, on top of the stack) is on the /left/ of the comparison symbol and the value pushed first (a) is on the right. So ~a b >X~ reads as "b > a", and ~a b <X~ reads as "b < a". GNU ~dc~'s manual gives the same example: ~1 2>a~ will invoke register ~a~'s contents (because 2 > 1), and ~2 1>a~ will not. You can try it in the Direct Console:

#+begin_example
[[FIRED] p] sa
1 2 >a
2 1 >a
#+end_example

The ~1 2 >a~ line prints FIRED; the ~2 1 >a~ line prints nothing.

*Loops* are built by having the macro in ~X~ call itself again (via ~l~ ... ~x~) as its last step, conditioned on not being done yet — this is recursion standing in for iteration, and it is exactly how the calculator's own trig, log, and statistics keys are implemented. See the factorial walkthrough in Section 6 for a minimal worked example.

** Precision, base, and output control

| Command | Effect                                                             |
|---------+--------------------------------------------------------------------|
| ~k~     | Pop a value, set the decimal precision (scale) to that many digits |
| ~K~     | Push the current precision                                         |
| ~i~     | Pop a value, set the input number base to that value               |
| ~I~     | Push the current input base                                        |
| ~o~     | Pop a value, set the output number base to that value              |
| ~O~     | Push the current output base                                       |

Setting ~o~ to 16 prints results in hexadecimal; setting ~i~ to 2 reads typed numbers as binary. These are commonly saved/restored around a macro (push the old base, run the macro, restore it) so a subroutine's internal math doesn't leak a base change to the caller — that's what the ~K s_ ... l_ k~ pattern you'll see throughout Section 6 is doing: /save the current precision in register ~_~, run the body, restore it at the end./

** Comments and misc

| Command | Effect                                                                                                                              |
|---------+-------------------------------------------------------------------------------------------------------------------------------------|
| ~#~     | Comment — rest of the line is ignored (standard ~dc~; not commonly needed inside this app's single-line macros)                     |
| ~q~     | Quit one level of macro execution                                                                                                   |
| ~Q~     | Pop a count and quit that many levels of nested macro execution                                                                     |
| ~z~     | Push the current stack depth                                                                                                        |
| ~Z~     | Pop a value and push the number of digits it has                                                                                    |
| ~_~     | Prefix for a negative number literal, e.g. ~_5~ is negative five (since ~-~ is the subtraction operator and can't double as a sign) |

** A quick worked program

Sum the integers 1 through 5 using a self-referencing macro:

#+begin_example
0 si              # running total in register i, start at 0
5 sn              # counter in register n, start at 5
[ li + sn 0 sn 1 - d 0 <L ] ...
#+end_example

(the full idiom is shown end-to-end in Section 6, which walks a real macro from this calculator's own source line by line).

* 6. Worked Example: The Factorial Macro

The ~n!~ key runs this exact macro, taken verbatim from the app's own source:

#+begin_example
[R1q]sB[d2>Bd1-d1<F*]dsFx
#+end_example

That's the whole program, and it computes ~n!~ for whatever non-negative integer is sitting in X — including the edge cases ~0!~ and ~1!~, both of which correctly give ~1~. Here it is broken into pieces, read left to right:

| Piece       | Meaning                                                                                                                                  |
|-------------+------------------------------------------------------------------------------------------------------------------------------------------|
| ~[R1q]~     | Pushed as a macro string: *R* discards the top of stack, *1* pushes 1, *q* quits two levels of execution (see below)                     |
| ~sB~        | Stores that base-case macro in register ~B~                                                                                              |
| ~[~ ... ~]~ | Everything between these brackets is the main macro body, pushed as a string (not run yet)                                               |
| ~d~         | /(inside the macro)/ Duplicate the top of stack — two copies of the current number                                                       |
| ~2~         | Push the literal 2                                                                                                                       |
| ~>B~        | With ~n 2 >B~ (a = ~n~, b = 2), executes register ~B~'s base-case macro when 2 > n, i.e. when n is less than 2 (see Section 5)           |
| ~d1-d1<F~   | Duplicate ~n~, subtract 1, duplicate again, and — if that's still greater than 1 — recurse by executing the macro stored in ~F~ (itself) |
| ~*~         | Multiply the top two stack values together                                                                                               |
| ~]~         | End of macro body                                                                                                                        |
| ~d~         | /(outside the macro, after the closing bracket)/ Duplicate the macro string itself — one copy to store, one to run immediately           |
| ~sF~        | Store one copy of the macro into register ~F~, so the recursive call inside the macro (~<F~) can find it                                 |
| ~x~         | Execute the remaining copy of the macro, kicking off the whole computation                                                               |

*Tracing ~4!~:* Start with ~4~ on the stack, then run the main body.

1. ~d~ → duplicate: stack is now ~4, 4~ (top first)
2. ~1-~ → subtract 1 from the top: ~3, 4~
3. ~d~ → duplicate the top again: ~3, 3, 4~
4. the literal ~1~ is pushed: ~1, 3, 3, 4~
5. ~<F~ pops the top two (~1~ and ~3~) to compare them. Reading it as in Section 5, ~a b <F~ fires when b < a; here a = ~3~ and b = ~1~, and 1 < 3, so it runs the macro stored in ~F~, which is this same macro, on whatever's left: ~3, 4~

That recursive call repeats the same five steps on ~3, 4~, then on ~2, 3, 4~, and so on — each level peels one more number off and calls itself again, until the comparison in step 5 finally fails (once the value being tested drops to ~1~, it's no longer greater than the literal ~1~, so ~F~ is /not/ invoked that time). At that point there's no more ~<F~ call left to make, and every level's trailing ~*~ fires in turn as the recursion unwinds, multiplying its way back out: ~4×3=12~, then that chain continues multiplying ~4×3×2~, giving ~24~.

The ~2>B~ check at the very start handles ~0!~ and ~1!~ directly, before any of this recursion begins: if ~n~ is less than 2, ~B~'s macro discards it and pushes ~1~, then ~q~ unwinds back out of both the ~B~ frame and the enclosing ~F~ frame — skipping the ~d1-d1<F*~ recursion entirely, so the trailing multiplications never run for those two inputs.

The practical takeaway: *a ~dc~ macro that stores itself in a register and calls that register conditionally is how every loop in this calculator's engine is built* — the trig functions, ~ln~/~lg~, the statistics keys, and the date-math macros you used in Section 3 all follow this exact pattern, just with longer bodies and more registers in play.

If you want to see this for yourself rather than take it on faith, the Direct Console (Section 4) is the place to do it: paste ~4 [] sF d1-d1<F* f~ (note the empty ~[]~ in place of the real macro) and you'll see the stack after just one pass through steps 1–5 above — a safe way to inspect one level of any recursive macro without triggering the recursion itself.

*"n!" vs. "x!" — factorial vs. the Gamma function.* This app actually has two different factorial-ish keys, and they are not interchangeable:

- */n!/* (SHIFT-blue on *lastx*) runs this exact ~FACTORIAL~ macro — exact arbitrary-precision integer factorial, for non-negative integers only.
- */x!/* (SHIFT on *yˣ*) runs a completely different macro, ~GAMMA~, that computes the mathematical Gamma function Γ(x) via a Stirling-series approximation. Γ extends factorial to /any/ real (even fractional) input — but Γ(x) = (x−1)!, *not* x!, for positive integers. So Γ(5) = 24 = 4!, not 120 = 5!. If you press /x!/ expecting ordinary factorial, you'll be off by one factor: either feed it x+1, or just use /n!/ instead whenever your input is a plain non-negative integer and you want exact ordinary factorial. Reach for /x!/ only when you actually need Gamma of a non-integer (e.g. Γ(0.5) = √π), where /n!/ can't help at all since it isn't defined for non-integers.

* 7. Tips, Troubleshooting, and Differences From Standard dc

*This isn't quite your system's ~dc~.* The engine behind this app is a from-scratch, arbitrary-precision reimplementation inspired by the classic Unix ~dc~ — not a port of GNU ~dc~ or BSD ~dc~. It follows the same core design (stack, registers, macros, postfix comparisons) and most of the same command letters, but:

- It uses true arbitrary-precision decimal arithmetic throughout (no float rounding error, no fixed word size), where a system ~dc~ is typically bound by its host's number representation.
- Not every obscure command from a given platform's ~dc~ is necessarily implemented — if you paste a script from elsewhere and a command does nothing or errors, check it against Section 5's table first.
- It runs sandboxed with safety limits on execution time, recursion depth, stack size, and similar, so a runaway or infinite macro will be stopped rather than hang the page.

*The two calculators don't talk to each other.* This is probably the single most common point of confusion: a value you ~s~tore on the Direct Console is not visible to the keypad calculator's registers, and the LASTX the keypad tracks has no bearing on the Direct Console. If something "disappeared," check whether you're looking in the other one.

*If a result looks wrong:* check the ~i~/~o~/~k~ indicator near the Direct Console header (or the keypad's own i/o/k info display) — a stray base change (~i~/~o~) or a very low precision (~k~) is the most common cause of a surprising-looking number. Resetting with the *clear* popup's *CLALL* (keypad) or a fresh ~0k~ (Direct Console) is a safe way to get back to a known state.

*Working on iOS vs. Android/Chrome.* The app is built to behave the same on both, but a couple of things are inherently platform-specific and worth knowing about rather than being surprised by:

- On iOS, the Direct Console textarea leaves extra space at the bottom for the home-indicator strip (the safe-area inset); Android/Chrome doesn't need this, so the two platforms' panels aren't pixel-identical, by design.
- The on-screen keyboard behaves differently across the two platforms; the Direct Console tries to grow the typing area to make room for it either way, but a very small or unusually configured device is the one case worth testing directly rather than assuming it will look right.
- Pinch-zoom is intentionally disabled app-wide so the layout doesn't get knocked out of place by an accidental zoom gesture on a small screen.

*Updates.* When a new version is deployed, you'll see an update prompt the next time you open the Direct Console (Section 4) — accepting it reloads the app and clears old cached files, but keeps your saved calculator and Direct Console state.

Register-convention note: for every two-operand function, /Y is whatever you entered first, X is whatever you entered right before pressing the key/ — e.g. for nCr, put the pool size in Y and the number chosen in X.
